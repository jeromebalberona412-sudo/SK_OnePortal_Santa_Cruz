================================================================================
                            1. SYSTEM OVERVIEW
================================================================================

The SK One Portal Santa Cruz is a comprehensive multi-tenant web application 
system designed to manage Sangguniang Kabataan (SK) operations across Santa 
Cruz, Laguna. The system consists of four interconnected portals:

1. Admin Portal - Central management and oversight
2. SK Federation Portal - Municipal-level monitoring and coordination
3. SK Officials Portal - Barangay-level operations and management
4. Kabataan Portal - Youth registration and program participation

Technology Stack:
- Backend: Laravel (PHP)
- Frontend: Blade Templates, JavaScript, CSS
- Database: PostgreSQL/MySQL
- Authentication: Laravel Fortify
- Email: SMTP (Mailtrap for development)

                        3. ADMIN PORTAL PROCESSES
================================================================================

3.1 ACCOUNT MANAGEMENT PROCESS
-------------------------------

A. SK Federation Account Creation
   1. Admin logs into Admin Portal
   2. Navigate to "Manage SK Federation Accounts"
   3. Click "Add New Account"
   4. Fill in account details:
      - Name
      - Email
      - Barangay assignment
      - Term start/end dates
      - Position (SK Chairperson, Kagawad, etc.)
   5. System generates temporary password
   6. Account created with status "ACTIVE"
   7. Email notification sent to SK Federation user
   8. Audit log entry created

B. SK Officials Account Creation
   1. Admin logs into Admin Portal
   2. Navigate to "Manage SK Officials Accounts"
   3. Click "Add New Account"
   4. Fill in account details:
      - Name
      - Email
      - Barangay assignment
      - Term start/end dates
      - Position
   5. System generates temporary password
   6. Account created with status "ACTIVE"
   7. Email notification sent to SK Official
   8. Audit log entry created

C. Account Status Management
   - ACTIVE: Full access to portal
   - INACTIVE: Temporarily suspended
   - DEACTIVATED: Permanently disabled
   - PENDING_APPROVAL: Awaiting admin approval

D. Term Extension Process
   1. Admin selects official profile
   2. Click "Extend Term"
   3. Enter new end date
   4. System validates date (must be future date)
   5. Term extended
   6. Audit log entry created

E. Password Reset Process
   1. Admin selects user account
   2. Click "Reset Password"
   3. Option 1: Generate random password
   4. Option 2: Set custom password
   5. New password sent via email
   6. User must change on first login

   6. Send rejection email with reasons

                        6. KABATAAN PORTAL PROCESSES
================================================================================

6.1 KK PROFILING REGISTRATION
------------------------------

A. Registration Flow
   1. Visit Kabataan Portal
   2. View signup page with barangay list
   3. Check barangay schedule status:
      - ONGOING: Can register
      - UPCOMING: Registration not yet open
      - COMPLETED: Registration closed
      - CANCELLED: Registration unavailable
   4. Select barangay
   5. System checks if schedule is active
   6. If active, proceed to registration form
   7. If not active, show error message

B. Registration Form Fields
   PERSONAL INFORMATION:
   - Last name (required)
   - First name (required)
   - Middle name (optional)
   - Suffix (optional)
   - Purok/Zone (required)
   - Sex (required: Male/Female)
   - Age (required: 15-30)
   - Birthday (required)
   - Email (required)
   - Contact number (optional)

   CLASSIFICATION:
   - Civil status (Single, Married, Widowed, Separated)
   - Youth classification (In-School, Out-of-School, Working, etc.)
   - Youth age group (Child Youth, Core Youth, Young Adult)
   - Work status (Employed, Unemployed, Student, etc.)
   - Education level

   VOTER INFORMATION:
   - SK voter (Yes/No)
   - National voter (Yes/No)
   - SK voted in last election (Yes/No)
   - Vote frequency

   PARTICIPATION:
   - KK Assembly attendance (Yes/No)
   - Reasons for non-attendance (if applicable)

   SOCIAL MEDIA:
   - Facebook account
   - Group chat participation

   SIGNATURE:
   - Digital signature (required)

C. Form Submission Process
   1. Fill out all required fields
   2. Click "Submit"
   3. System validates data
   4. Check for existing registration (by email + barangay)
   5. If exists, update registration
   6. If new, create registration
   7. Set status to "pending_verification"
   8. Generate verification URL (valid 24 hours)
   9. Send verification email
   10. Redirect to "Check Email" page

D. Email Verification Process
   1. Kabataan receives verification email
   2. Click verification link
   3. System validates signed URL
   4. Check if link is expired
   5. If valid, mark email as verified
   6. Update status to "email_verified"
   7. Store registration ID in session
   8. Redirect to "Set Password" page

E. Password Setup Process
   1. View "Set Password" page
   2. Enter password (minimum 8 characters)
   3. Confirm password
   4. Click "Set Password"
   5. System validates password
   6. Check session for registration ID
   7. Create or update user account:
      - Name: Full name from registration
      - Email: From registration
      - Password: Hashed password
      - Role: "kabataan"
      - Status: "PENDING_APPROVAL"
      - Tenant ID: From barangay
      - Barangay ID: From registration
   8. Mark password as set
   9. Mark registration as active

F. Auto-Approval Evaluation
   1. System runs evaluation service
   2. Check against previous kabataan records
   3. Match criteria:
      - Same name
      - Same barangay
      - Similar age
      - Previous registration exists
   4. If match found:
      - Auto-approve registration
      - Update user status to "ACTIVE"
      - Send approval email
      - Kabataan can log in immediately
   5. If no match:
      - Keep status as "PENDING_APPROVAL"
      - Wait for SK Official review
      - Send pending notification

G. Registration Status Flow
   pending_verification → email_verified → password_set → 
   PENDING_APPROVAL → ACTIVE (or REJECTED)

                        7. INTER-PORTAL WORKFLOWS
================================================================================

7.1 ACCOUNT CREATION WORKFLOW
------------------------------

Admin → SK Federation/Officials
1. Admin creates account in Admin Portal
2. System generates credentials
3. Email sent to SK Federation/Official
4. SK Federation/Official receives email
5. First login requires password change
6. Account activated

7.2 KK PROFILING WORKFLOW
--------------------------

Kabataan → SK Officials → System
1. Kabataan registers via Kabataan Portal
2. Email verification sent
3. Kabataan verifies email
4. Kabataan sets password
5. System evaluates against previous records
6. If match: Auto-approve
7. If no match: Send to SK Officials for review
8. SK Official reviews in SK Officials Portal
9. SK Official approves/rejects
10. Notification sent to Kabataan
11. If approved: Kabataan can log in
12. If rejected: Kabataan cannot access

7.3 PROGRAM MANAGEMENT WORKFLOW
-------------------------------

SK Officials → Kabataan → SK Federation
1. SK Official creates program in SK Officials Portal
2. Program published to Kabataan Portal
3. Kabataan views and applies
4. SK Official reviews applications
5. SK Official approves participants
6. Program conducted
7. SK Official submits program report
8. Report visible to SK Federation
9. SK Federation monitors compliance

7.4 ABYIP REPORTING WORKFLOW
----------------------------

SK Officials → SK Federation → Admin
1. SK Official prepares ABYIP report
2. SK Official submits via SK Officials Portal
3. Report stored in database
4. SK Federation views in monitoring dashboard
5. SK Federation reviews compliance
6. If non-compliant: Warning issued
7. Admin can view all reports
8. Admin generates municipal summary

7.5 MONITORING WORKFLOW
-----------------------

SK Federation → SK Officials → Admin
1. SK Federation monitors barangay compliance
2. Check report submissions
3. Check program implementation
4. Calculate compliance status
5. If non-compliant: Issue warning
6. SK Officials receive notification
7. SK Officials submit missing reports
8. Compliance status updated
9. Admin oversees entire process

                        10. TECHNICAL SPECIFICATIONS
================================================================================

10.1 DATABASE STRUCTURE
-----------------------

Key Tables:
- users: All user accounts (Admin, SK Fed, SK Officials, Kabataan)
- tenants: Municipality/tenant information
- barangays: Barangay master data
- kabataan_registrations: KK Profiling submissions
- previous_kabataan: Historical profiling records
- official_profiles: SK Official profile details
- terms: Official term information
- kk_profiling_schedules: Registration schedule management
- programs: Sports, scholarship, and other programs
- program_applications: Program application submissions
- announcements: Announcement posts
- events: Calendar events
- abyip_reports: ABYIP report submissions
- audit_logs: System audit trail

10.2 USER ROLES
---------------
- admin: Super administrator
- sk_federation: Municipal SK Federation
- sk_official: Barangay SK Official
- kabataan: Youth/citizen

10.3 STATUS VALUES
------------------

User Status:
- ACTIVE: Full access
- PENDING_APPROVAL: Awaiting approval
- REJECTED: Access denied
- INACTIVE: Temporarily suspended
- DEACTIVATED: Permanently disabled

Registration Status:
- pending_verification: Email not verified
- email_verified: Email verified, password not set
- password_set: Password set, awaiting approval
- active: Approved and active
- rejected: Rejected by SK Official
- archived: Moved to archive

Evaluation Status:
- Not Profiled: New registration
- Wrong Credentials: Information mismatch
- Duplicate: Already registered
- Auto Approved: Automatically approved
- active: Manually approved

Schedule Status:
- Ongoing: Currently accepting registrations
- Upcoming: Will open soon
- Rescheduled: Date changed
- Completed: Registration closed
- Cancelled: Registration cancelled

================================================================================
                            11. BUSINESS RULES
================================================================================

11.1 REGISTRATION RULES
------------------------
- Age requirement: 15-30 years old
- One registration per email per barangay
- Email verification required
- Password minimum 8 characters
- Registration only during active schedule
- Auto-approval if matched with previous records
- Manual approval required for new registrations

11.2 ACCOUNT RULES
------------------
- Unique email per user
- One role per user
- Term dates must be valid
- Barangay assignment required for SK Officials
- Admin can manage all accounts
- SK Officials can only manage their barangay

11.3 COMPLIANCE RULES
---------------------
- ABYIP report required quarterly
- Accomplishment report required per program
- Compliant: Both reports submitted this year
- Partial: One report missing
- Non-compliant: No reports this year
- Warning issued for non-compliance

11.4 PROGRAM RULES
------------------
- Program must have schedule
- Participant limit can be set
- Application deadline required
- Approval required for participation
- Report required after completion
